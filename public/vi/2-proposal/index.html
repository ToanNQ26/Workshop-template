Bản đề xuất

AI Web Chat trên AWS với EC2, RDS và Amazon Bedrock

Kiến trúc Web Chat tích hợp AI tối ưu chi phí và có khả năng mở rộng

1. Tóm tắt điều hành

Đề xuất này trình bày giải pháp kiến trúc cho một hệ thống Web Chat tích hợp AI được triển khai trên nền tảng điện toán đám mây AWS. Hệ thống cho phép người dùng đăng ký, đăng nhập, tạo cuộc trò chuyện và tương tác với AI thông qua giao diện Web.

Backend của ứng dụng được triển khai trên Amazon EC2 để có môi trường chạy ổn định và linh hoạt cho Web Chat. EC2 kết nối tới Amazon RDS, là cơ sở dữ liệu quan hệ dùng để lưu trữ dữ liệu người dùng, cuộc trò chuyện và tin nhắn theo mô hình có cấu trúc rõ ràng. Amazon Bedrock được tích hợp để xử lý các yêu cầu AI.

Frontend của ứng dụng được triển khai trên Amazon S3 và phân phối thông qua Amazon CloudFront. Amazon API Gateway có thể được sử dụng làm lớp API ở phía trước Backend để quản lý endpoint và bảo vệ request. Amazon CloudWatch theo dõi log, metrics và tình trạng hoạt động của EC2, RDS và các thành phần liên quan.

Hệ thống sử dụng Amazon CloudWatch để ghi log, theo dõi hoạt động và phát hiện lỗi trong quá trình vận hành.

2. Tuyên bố vấn đề

Vấn đề hiện tại

  • Chi phí duy trì Backend: Việc sử dụng một máy chủ Backend truyền thống yêu cầu tài nguyên hoạt động liên tục ngay cả khi không có người dùng, dẫn đến chi phí không cần thiết trong thời gian thấp điểm.

  • Khả năng mở rộng hạn chế: Khi số lượng người dùng và request tăng, một Backend server cố định có thể trở thành điểm nghẽn và yêu cầu người quản trị phải chủ động mở rộng tài nguyên.

  • Tích hợp AI: Hệ thống cần kết nối với mô hình AI để xử lý nội dung người dùng gửi. Việc gọi AI với số lượng request và token lớn có thể làm chi phí tăng nhanh nếu không có cơ chế kiểm soát.

  • Lưu trữ lịch sử hội thoại: Web Chat cần lưu trữ conversation và message. Hệ thống cần một cơ sở dữ liệu có khả năng mở rộng và phù hợp với dữ liệu có cấu trúc linh hoạt.

  • Theo dõi và xử lý lỗi: Khi Backend và AI được phân tách thành nhiều thành phần, cần có cơ chế logging và monitoring để xác định lỗi trong quá trình xử lý request.

Giải pháp đề xuất

Hệ thống được thiết kế theo mô hình hybrid cloud, kết hợp EC2 cho Backend, RDS cho dữ liệu quan hệ và các dịch vụ managed service của AWS cho frontend, AI, monitoring và bảo mật.

Kiến trúc được chia thành 4 luồng xử lý chính:

  1. Flow A - Frontend Distribution: Frontend được build thành các static assets và lưu trữ trên Amazon S3. Amazon CloudFront được sử dụng để phân phối nội dung đến người dùng.

  2. Flow B - User Request & API Processing: Người dùng gửi request thông qua giao diện Web. Request đi qua Amazon API Gateway và được chuyển tới Backend chạy trên Amazon EC2 để xử lý logic ứng dụng.

  3. Flow C - AI Chat Processing: Backend trên EC2 tiếp nhận message, kiểm tra dữ liệu, gọi Amazon Bedrock để tạo AI response, sau đó lưu kết quả vào Amazon RDS.

  4. Flow D - Data & Monitoring: Amazon RDS lưu trữ thông tin người dùng, conversation và message bằng các bảng quan hệ. Amazon CloudWatch ghi nhận log và metrics từ EC2, RDS, API Gateway và ứng dụng Backend.

Lợi ích và Hoàn vốn đầu tư (ROI)

  • Kiểm soát môi trường Backend: EC2 cho phép lựa chọn hệ điều hành, runtime, thư viện và cấu hình phù hợp với ứng dụng.

  • Khả năng mở rộng: EC2 có thể được nâng cấp hoặc kết hợp với Auto Scaling khi lượng request tăng; RDS có thể mở rộng tài nguyên và bật Multi-AZ khi cần.

  • Dữ liệu nhất quán: RDS hỗ trợ mô hình quan hệ, transaction, khóa ngoại và truy vấn lịch sử hội thoại rõ ràng.

  • Tích hợp AI linh hoạt: Amazon Bedrock cung cấp API để ứng dụng có thể tích hợp mô hình AI mà không cần tự triển khai và quản lý GPU infrastructure.

  • Khả năng giám sát: CloudWatch cung cấp log và metrics để theo dõi EC2, RDS, API và các lỗi trong quá trình xử lý.

Chi tiết 4 luồng xử lý chính trong kiến trúc

1. Flow A - Frontend Distribution

  • A1: Người dùng truy cập Web Chat thông qua giao diện Web.

  • A2: Amazon CloudFront tiếp nhận request và phân phối các static assets của frontend.

  • A3: Các file frontend sau khi build được lưu trữ trên Amazon S3.

  • A4: CloudFront cache các nội dung phù hợp nhằm giảm số request trực tiếp tới S3 và cải thiện tốc độ tải trang.

2. Flow B - API Request & Backend Processing

  • B1: Người dùng thực hiện một thao tác trên Web Chat, ví dụ đăng nhập, tạo cuộc trò chuyện, gửi message hoặc lấy lịch sử hội thoại.

  • B2: Frontend gửi HTTPS request tới Amazon API Gateway.

  • B3: API Gateway tiếp nhận request và chuyển tới Backend đang chạy trên EC2.

  • B4: Backend trên EC2 thực hiện xác thực request, xử lý business logic và giao tiếp với RDS, Bedrock hoặc các dịch vụ AWS khác.

3. Flow C - AI Chat Processing

  • C1: Người dùng nhập nội dung tin nhắn và gửi tới hệ thống.

  • C2: API Gateway chuyển request tới Backend trên EC2.

  • C3: Backend kiểm tra thông tin người dùng và chuẩn bị prompt gửi tới Amazon Bedrock.

  • C4: Amazon Bedrock xử lý prompt bằng mô hình AI được lựa chọn.

  • C5: AI response được trả về Backend trên EC2.

  • C6: Backend lưu message của người dùng và AI response vào RDS.

  • C7: Response được trả về API Gateway và hiển thị trên giao diện Web Chat.

4. Flow D - Data & Monitoring

  • D1: Amazon RDS lưu trữ thông tin người dùng, conversation và message trong các bảng có quan hệ.

  • D2: Backend trên EC2 ghi log trong quá trình xử lý request.

  • D3: Amazon CloudWatch thu thập log và metrics từ EC2, RDS, API Gateway và ứng dụng.

  • D4: CloudWatch được sử dụng để theo dõi CPU, memory, trạng thái EC2, database connections, số lượng request, lỗi và các vấn đề phát sinh.

Dịch vụ AWS sử dụng

  • Amazon S3: Lưu trữ frontend và các static assets của Web Chat.

  • Amazon CloudFront: Phân phối frontend thông qua CDN và cải thiện tốc độ truy cập.

  • Amazon API Gateway: Cung cấp các API endpoint và tiếp nhận request từ frontend.

  • Amazon EC2: Chạy Backend và cung cấp môi trường thực thi cho ứng dụng Web Chat.

  • Amazon RDS: Cung cấp cơ sở dữ liệu quan hệ cho users, conversations và messages.

  • Amazon Bedrock: Cung cấp khả năng xử lý AI cho Web Chat.

  • Amazon CloudWatch: Monitoring, logging và theo dõi lỗi của hệ thống.

  • AWS IAM: Quản lý quyền truy cập giữa các AWS services theo nguyên tắc Least Privilege.

4. Triển khai kỹ thuật

Các giai đoạn triển khai

  1. Giai đoạn 1: Nghiên cứu và thiết kế kiến trúc

    • Phân tích yêu cầu của hệ thống Web Chat.
    • Xác định các chức năng chính của ứng dụng.
    • Thiết kế kiến trúc tổng thể trên AWS.
    • Xác định các dịch vụ AWS cần sử dụng.
    • Thiết kế mô hình dữ liệu quan hệ cho Amazon RDS.
    • Xác định luồng request giữa Frontend, API Gateway, EC2, RDS và Bedrock.

  2. Giai đoạn 2: Xây dựng Backend trên EC2

    • Thiết lập Amazon API Gateway.
    • Tạo và cấu hình Amazon EC2.
    • Cài đặt runtime, thư viện và Backend application trên EC2.
    • Thiết lập Amazon RDS và schema quan hệ.
    • Xây dựng API quản lý người dùng.
    • Xây dựng API quản lý conversation.
    • Xây dựng API gửi và lấy message.
    • Thiết lập IAM Role và Security Group cho EC2.

  3. Giai đoạn 3: Tích hợp AI

    • Thiết lập quyền truy cập Amazon Bedrock.
    • Lựa chọn mô hình AI phù hợp với yêu cầu và ngân sách.
    • Tích hợp Amazon Bedrock vào Backend trên EC2.
    • Xây dựng prompt cho AI.
    • Xử lý AI response.
    • Lưu lịch sử hội thoại vào RDS.
    • Kiểm soát độ dài prompt và response nhằm tối ưu chi phí.

  4. Giai đoạn 4: Triển khai Frontend

    • Hoàn thiện giao diện Web Chat.
    • Build ứng dụng frontend.
    • Upload static assets lên Amazon S3.
    • Cấu hình Amazon CloudFront.
    • Kết nối Frontend với API Gateway.
    • Kiểm thử chức năng đăng nhập, tạo conversation và chat với AI.

  5. Giai đoạn 5: Monitoring, kiểm thử và tối ưu

    • Thiết lập Amazon CloudWatch Logs.
    • Theo dõi EC2, RDS và API request.
    • Kiểm thử các API endpoint.
    • Kiểm thử luồng gửi message và nhận AI response.
    • Kiểm tra khả năng xử lý nhiều request.
    • Theo dõi mức sử dụng các dịch vụ AWS.
    • Kiểm tra chi phí phát sinh.
    • Tối ưu EC2, RDS và Amazon Bedrock.
    • Hoàn thiện tài liệu và báo cáo thực tập.

Yêu cầu kỹ thuật và bảo mật

  • Quản lý quyền truy cập: Sử dụng IAM Role cho EC2 và thông tin xác thực được quản lý an toàn thay vì lưu Access Key trực tiếp trong source code.

  • Least Privilege: EC2 chỉ được cấp các quyền cần thiết đối với RDS, Bedrock, CloudWatch và các dịch vụ liên quan.

  • HTTPS: API được cung cấp thông qua Amazon API Gateway và sử dụng HTTPS để bảo vệ dữ liệu truyền giữa client và server.

  • Bảo vệ thông tin xác thực: Không lưu Access Key, Secret Key hoặc các thông tin nhạy cảm trực tiếp trong source code.

  • Kiểm soát AI Request: Giới hạn kích thước prompt và response để hạn chế chi phí và tránh các request bất thường.

  • Validation: Kiểm tra và xác thực dữ liệu đầu vào trước khi xử lý nhằm hạn chế các request không hợp lệ.

  • Logging: Các hoạt động và lỗi của Backend được ghi nhận thông qua Amazon CloudWatch.

  • Monitoring: Theo dõi các chỉ số quan trọng của EC2, RDS và API Gateway để phát hiện vấn đề trong quá trình vận hành.

6. Ước tính ngân sách

Do hệ thống được triển khai trong phạm vi một dự án thực tập và lượng truy cập dự kiến thấp, kiến trúc sử dụng EC2 và RDS ở quy mô nhỏ, kết hợp mô hình pay-as-you-go nhằm kiểm soát chi phí vận hành.

Dịch vụ AWSCấu hình / Quy mô ước tínhChi phí dự kiến

Tối ưu chi phí:

  1. Chọn loại EC2 và RDS nhỏ phù hợp với workload thử nghiệm.
  2. Dừng hoặc xóa EC2, RDS và các tài nguyên không cần thiết sau mỗi buổi thực hành.
  3. Theo dõi thời gian chạy instance và dung lượng RDS để tránh phát sinh chi phí ngoài dự kiến.
  4. Lựa chọn mô hình Amazon Bedrock phù hợp với yêu cầu và ngân sách.
  5. Giới hạn số lượng request tới Amazon Bedrock.
  6. Giới hạn số token trong prompt và AI response.
  7. Theo dõi mức sử dụng thông qua AWS Billing và CloudWatch.
  8. Xóa các tài nguyên thử nghiệm không còn sử dụng sau khi hoàn thành.

  • Triển khai Frontend trên AWS: Frontend được lưu trữ trên Amazon S3 và phân phối thông qua Amazon CloudFront.
  • Monitoring: Amazon CloudWatch được sử dụng để theo dõi log, metrics và hoạt động của hệ thống.
  • Bảo mật: Hệ thống áp dụng AWS IAM và nguyên tắc Least Privilege để kiểm soát quyền truy cập giữa các thành phần.
  • Tối ưu chi phí: Chọn cấu hình EC2/RDS nhỏ, theo dõi mức sử dụng và dọn dẹp tài nguyên sau khi thử nghiệm.
  • Giá trị học tập: Đề tài giúp áp dụng thực tế AWS Core Services, Networking, EC2, RDS, Monitoring và AI Services.

Kết luận

Đề xuất hướng tới việc xây dựng một hệ thống Web Chat tích hợp AI trên AWS với kiến trúc hybrid, sử dụng EC2 cho Backend, RDS cho dữ liệu quan hệ và phù hợp với quy mô của một dự án thực tập.

Việc kết hợp Amazon S3, Amazon CloudFront, Amazon API Gateway, Amazon EC2, Amazon RDS, Amazon Bedrock, Amazon CloudWatch và AWS IAM giúp hệ thống có đầy đủ các thành phần cần thiết từ frontend, backend, lưu trữ dữ liệu, xử lý AI đến monitoring và bảo mật.

Trong quá trình triển khai thực tế, kiến trúc và các dịch vụ có thể được điều chỉnh dựa trên yêu cầu chức năng, hiệu năng, mức sử dụng tài nguyên và chi phí phát sinh thực tế.
